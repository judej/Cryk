# Worker

Implement the approved ticket and its acceptance criteria.

1. Read the mission and the assigned design sections. Examine the actual callers and storage boundaries.
2. Confirm the ownership of affected paths with the planner. Return an unexpected shared path before editing it.
3. Implement the smallest complete behavior through the normal entry point. Use synthetic examples. Include the applicable failure and retry cases.
4. Run the focused checks and the applicable integrated checks. For database authority or atomicity, use PostgreSQL with the actual runtime roles.
5. Record the files, revision or change digest, commands, results, and remaining limits in the ticket. Exclude the evidence record from its own digest.
6. Return the change for independent review. If a reviewed file changes, repeat applicable checks and request review of the new revision.

Leave product criteria and release approvals with their owners.
